# KustoCargo · 途序 — 网站设计简报

更新日期：2026-11-16。本文汇总访谈决定；标为“建议”或“待定”的内容尚未由用户逐项确认。用户随后要求整理可执行规格，相关工程默认值与文案基线已落入 [KustoCargo prompts](../.github/prompt/kusto-cargo/README.md)；它们属于实施设计选择，不冒充新的用户决定。

## 目标与受众（已确认）

- 面向约 2–20 人的小微货代公司及其经营者，主要服务中国企业与中欧物流网络。
- 网站用于产品宣传、吸引演示与试用申请，也供团队在客户拓展时介绍关键功能。
- 中文为主，同时提供英文；每种语言均为向下滚动的单页体验。
- 产品定位是标准版本加定制开发，由团队跟进客户需求，适配其流程、字段、单据和分工。
- 产品客户可选择团队托管或自行部署，强调客户对数据的拥有与管理。
- 网站介绍产品化愿景及可提供的方案，不以当前代码实现进度限定叙事。最终交付范围在客户沟通中确定。
- 核心主张方向：让系统适应客户的货代业务。最终标题与中英文文案待定。

## 业务故事（已确认）

欧洲客户向中国工厂采购，货代组织从工厂仓库、集货装柜、出口、跨海运输到目的港及最终派送的业务。

不同业务中，工厂、出口主体、进口主体、实际收发货人及代理可能不同；部分业务由买卖双方自行承担进出口角色，部分由其他参与方负责。页面应呈现货物流转与多方职责的连接，体现系统对多种实际流程的适配。

## 重点产品能力（已确认方向）

1. 团队提供流程、字段、单据和分工的定制开发。
2. 连接客户、工厂、收发货人、进出口主体及代理等多方信息。
3. 费用、报价、应收应付与利润管理。
4. AI 辅助读取单据、整理资料、检查缺失信息；同时提供对话侧栏和业务页面内的 AI 操作。
5. MCP 接入，使客户能够通过兼容的 Agent 连接业务系统，保留使用本地 Excel 等工作方式。
6. 自动货物追踪：接入海运、空运等不同追踪 API，汇总最新运输节点，减少逐个手动查询。具体供应商、更新频率与覆盖范围待后续产品集成确定。

### AI 权限（已确认）

AI 继承当前登录人员的权限，操作受同样的业务授权约束。出口人员登录时，AI 使用出口人员权限；非管理员的 AI 不得获得管理员权限。管理员登录时，AI 也只使用该管理员实际拥有的权限。

权限范围与操作确认机制是不同问题；哪些写入需要预览或确认、哪些重复任务可自动执行，尚未决定。

### 可继续探索的 AI 场景（建议）

从 Excel 和附件生成委托草稿、多方关系梳理、单据交叉核对、待办与异常汇总、报价草稿、费用分析与对账、中英文客户消息草稿。页面挑选的演示场景及具体文案待定。

## 品牌与视觉（已确认）

- 名称：**KustoCargo · 途序**。
- Logo：[第三轮探索图](brand/logo-exploration-v3.png) 中间的 **02「交错连接」**。
- Logo 使用深海蓝与青绿，去掉黄色/橙色装饰。探索图是方向参考，正式矢量资产和标准比例待制作。
- 网站采用混合主题：深色开场，浅色功能内容区。
- 开场突出中欧航线动画；后续功能区保持清晰、便于浏览。
- 产品功能用与真实业务一致的精简界面示意呈现。

### 页面故事与交互细化（建议）

- 深海蓝地图开场，品牌、主标题和演示/试用入口直接可见。
- 随滚动依次经过中国工厂、集货装柜、出口港、远洋运输、目的港和派送节点。
- 节点结合 AI 整理资料、连接参与方、单据核对和运输追踪等界面片段。
- 地图路线应匹配展示的运输方式；海运路线沿海上通道表达，不能将横穿陆地的概念连线当作海运轨迹。
- 航线收束后进入流程定制、协作、费用、AI、MCP、部署与数据选择等内容，再进入表单。确切分区顺序待定。
- 保留正常滚动和锚点导航；手机端简化镜头运动，减少动态效果设置下提供静态或轻动效版本。

## 演示与试用表单（已确认）

客户先申请演示或试用，由团队安排，随后进一步讨论业务需求。提交表单不等同于自动创建试用账号。

| 字段 | 规则 |
| --- | --- |
| 姓名 | 必填 |
| 公司 | 必填 |
| 邮箱 | 与微信至少填写一个；填写时校验格式 |
| 微信 | 与邮箱至少填写一个 |
| 手机号码 | 选填，不可替代邮箱或微信要求 |
| 意向 | 必选：演示 / 试用 |
| 需求说明 | 选填 |

邮箱和微信允许同时填写。表单接收方式由用户后续手动设置，见 [手动 TODO](manual-todo.md)。页面保持静态，实际收集提交需要另行接入接收端；接收端未配置时不能显示虚假的提交成功。

## 技术方案

**已确认：使用 Astro，以静态输出构建网站。** 配套工具已在实施规格中确定默认方案；具体兼容版本在实施阶段 01 核对并锁定。

| 层次 | 方案 | 状态 | 用途 |
| --- | --- | --- | --- |
| 页面 | Astro 静态生成 | 已确认 | 构建双语静态页面，保持内容直接可读 |
| 脚本 | TypeScript | 实施默认值 | 维护交互、动画与内容数据的类型约束 |
| 样式 | CSS 设计变量与组件样式 | 实施默认值 | 统一深浅主题、字体、间距和响应式布局 |
| 动画 | SVG + GSAP / ScrollTrigger | 实施默认值 | 航线绘制、货物移动、滚动分镜和节点展开 |
| 双语路由 | 中文 `/`，英文 `/en/` | 路径为实施默认值；双语已确认 | 各语言独立的单页和共享组件 |
| 托管 | Lightsail 上的静态 Web 服务 | Lightsail 已确认；默认准备 Nginx 模板并以现场服务为准 | 发布同一份静态构建产物，后续可复制到亚洲节点 |
| 表单 | 可配置的接收端 | 用户后续手动设置 | 用户决定接收服务和通知渠道 |

字体、图形与动画脚本优先随站点部署；航线地图用本地 SVG，不要求加载在线地图服务。CDN 是后续可选项，是否增加及亚洲节点如何设置，应以中国与欧洲的访问测试为依据。

技术依据（2026-11-16 查阅）：

- [Astro 静态预渲染](https://docs.astro.build/en/guides/on-demand-rendering/)：默认在构建时生成静态页面。
- [Astro 多语言路由](https://docs.astro.build/en/guides/internationalization/)：支持默认语言无路径前缀及其他语言前缀。
- [GSAP ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)：支持滚动驱动时间线和固定场景。
- [Lightsail 内容分发](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-content-delivery-network-distributions.html)：可从实例等源站缓存和分发静态内容。
